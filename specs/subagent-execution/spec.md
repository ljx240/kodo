# 子 Agent 执行与 Trace

## 目标与原则

遵循仓库 AGENTS.md：本地实现、最小改动、复用执行和审批链，不引入依赖，不读取凭据，不上传文件。基线为本地 `main` 的 `91fd94ecc5013e826d433bb9f8365251843bf791`；远程新鲜度未核验。原有未跟踪提示文件、技能查看器 worktree 和 7 条 stash 经用户确认原样保留。

现有 AgentSpec 是当前回合的角色指令，不是独立执行器。新增子 Agent 必须实际运行工具和模型，父 Agent 能得到结构化结果，用户能回看独立执行轨迹。

## 可验收行为

- FR-001：项目会话支持 `/subagent <任务>`，以及 `/subagent @reviewer <任务>` 等显式角色。缺少任务、项目、模型或角色无效时给出明确错误，不伪造已执行。
- FR-002：主 Agent 可调用 `subagent` 工具，参数为 `task`、可选 `agent` 和 `read_only`。工具等待子任务结束，返回结果或错误，父 Agent 可继续汇总、验证。
- FR-003：子任务拥有独立模型历史；继承项目、模式、当前请求的模型配置、沙箱、权限与可用工具上限。复用现有角色，不接受模型提供的新凭据、提供方或权限。
- FR-004：每轮最多 4 次委派，深度最多 1。子任务使用有界轮次、工具次数及执行时间。父任务停止或事件写入失败后子任务停止；超时、预算耗尽、blocked/partial、拒绝和模型失败不得标成成功。
- FR-005：只读父任务或 `read_only=true` 的子任务不可写文件、调用有副作用命令或不透明 MCP 工具。继承 skill 白名单，委派不能增加权限。
- FR-006：Trace 实时显示子任务 ID、父级 ID、角色、任务、执行状态、工具步骤、结果、耗时及 token。保存后重启仍可回看；中断不能展示为完成。子任务输出不得覆盖父会话最终回答，子步骤不得冒充父级验证证据。
- FR-007：子任务实际文件变更进入父回合的变更集、diff、undo 和重新验证流程。子任务不另建 Git 分支或 worktree。
- FR-008：子任务 Trace 仅本地保存公开步骤，文本和条数有上限并脱敏，不保存私有思考正文，不新增遥测。

## 使用

在选定项目的会话中输入 `/subagent 实现一个有明确验收条件的小任务`，或者 `/subagent @reviewer 检查路由并返回文件行号证据`。主 Agent 也可调用 `subagent` 工具；`read_only=true` 将子任务限制为只读。会话执行过程可展开子任务；“运行详情 → 子 Agent”可回看已保存的结果。

## 首版范围

采用进程内前台委派；同一工作目录顺序执行，防止并发写入。暂不包含后台续聊、并行写任务、跨进程协议、嵌套委派、跨模型调度和独立 worktree 自动管理。没有联网运行真实模型的授权，不执行真实提供方测试；使用本地 mock 覆盖执行协议。

子任务限制为 12 轮、32 次模型工具调用、1 次修复及 120 秒合作式执行检查；同步审批或阻塞 I/O 返回前不强制杀死线程，仍遵循既有提供方与进程超时。公开 Trace 最多保留 48 个步骤，超额显示省略数，结果最多保留 8000 字。

## 普通任务自动委派（2026-10-22）

用户无需主动输入 `/subagent` 或点选角色。默认由当前主模型根据任务语义、工作量和可拆分性决定是否调用已有的 `subagent` 工具；不使用关键词命中就启动子任务的硬编码规则。显式命令作为兼容入口保留。

- FR-011：普通任务包含有独立目标和验收条件的实质性工作时，主模型按需选取有边界的子任务自动委派，说明范围后实际调用工具，再汇总返回证据；不要求用户另行请求子 Agent。
- FR-012：简单问答、局部小修改和例行验证由主模型直接完成；尊重用户不委派的要求。每次只委派一个模块或一个聚焦问题，不把全部独立部分整体转交；仅传递所需上下文，并给出能在现有 120 秒预算内完成的简短产物与验收条件。同一工作目录中的子任务继续顺序执行。
- FR-013：自动策略在主系统提示的工具协议之前注入，并通过同一工具定义到达 native 和 JSON fallback 协议；没有项目、技能不允许或当前已是子任务时，不提示使用不可用的委派工具。自动委派仍受原有权限、只读、深度、数量、预算、取消及 Trace 约束。
- FR-014：子任务真实文件变更推进父级编辑证据，但不能代替父级汇总；委派结果返回后清除旧完成声明，父级验证后继续剩余工作并给出新正文。失败子任务若已有实际文件变更，也使先前验证失效。
- AC-012：回归主提示的策略顺序，以及 native schema 与 fallback 提示中的同一自动策略及子 Scope/技能/无项目过滤后的不可用性。
- AC-013：不含 `/subagent`、角色或委派要求的普通任务，经真实 run 入口收到模型的工具调用后运行子任务，父级继续汇总；简单任务直接回答，无子 Trace。取消及失败状态仍如实呈现。
- AC-014：获得联网授权后，只用全新合成项目让真实模型自主判断复杂任务与简单任务；核对实际子工具执行、父级结果、取消及 Trace 保存/重载。未获授权时明确标记未验证，不用 mock 结果代替模型自主判断。

- AC-015：回归委派写入→父级验证→继续剩余写入→父级新汇总；旧完成声明无效，部分失败的实际变更不能沿用旧验证。
