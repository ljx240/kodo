# Jev 决策辅助

日期：2026-10-20。来源：`/Users/lijianxue/.codex/visualizations/2026/10/19/01a15364-e01b-74b3-ba4f-276e16c6f75b/kodo-jev-detailed-design-2026-10-19.md`（评审后规格）。工程原则见仓库 `AGENTS.md`。

## 1. 目标

在 Kodo 中增加一个**默认关闭、可独立回退**的 Jev 决策组件：主模型继续理解复杂需求、生成代码和组织回答；Kodo 的规则继续控制权限、预算、执行和验收。Jev 只在两处提供有界选项：模糊任务的类别选择、模糊失败的归类。

首期只交付 Observe（记录建议）与受控 Assist（按场景有限采纳）的**本地实现与模拟验收**。真实启用受第 6 节质量门控制。

### 服务来源（provider）

决策请求可以走两个服务之一，**一次只启用一个**：

| provider | 接收方 | 凭据 | 请求/响应 |
| --- | --- | --- | --- |
| `typeSafe` | `https://api.typesafe.ai/v1/systemone` | `decision.jev` | System One 原生格式：请求 `{model, state, questions}`，响应 `answers` 带概率分布 |
| `openRouter` | `https://openrouter.ai/api/v1/chat/completions` | `decision.openrouter` | OpenAI 兼容 chat completions：请求单字母选择 + `logprobs`，概率由首 token 的候选归一化得到 |

约束：

- **失败不自动换源**。TypeSafe 失败不会改投 OpenRouter，反之亦然：换源等于把同一份内容发给用户没有批准过的第二个接收方。
- 凭据按 provider 隔离，各自的密钥只发给各自的服务。
- `openRouter` 的模型 id 由用户指定（默认 `typesafe/jev-1.14` —— 路由器是传输，模型仍是评估所依据的那一个），与 TypeSafe 的固定版本（`jev-1.13.0`）是两件事。
- 响应里的模型必须与请求的模型一致（允许路由解析出的日期后缀与 provider 前缀），否则拒绝。
- **没有概率分布的答案不采纳**。路由器不返回 token 概率时，答案只作为观察记录，`applied` 恒为 false —— 门槛假设的是真实概率，不是模型的自评。

## 4. 行为边界（必须保持）

- 显式技能、Work/Code 模式、用户约束、无项目限制和文件产出契约优先于 Jev。
- 首期任务分类只影响已有任务通道内允许调整的 TaskType，不借此重写咨询/执行通道。
- 明确的用户拒绝、取消、权限故障、命令不存在、工作区冲突和预算耗尽不交给 Jev 推翻。
- Jev 不增加权限、修复次数或执行预算，不自动安装依赖、重试危险操作或修改模型目的地。
- 模型评分不能作为文件已写入、测试已通过或任务已完成的证据。
- Observe 只记录建议；Assist 仅在场景适用、响应合法、阈值满足且硬约束复核通过后采纳。
- 取消时停止本轮，不允许以"回退"为由继续运行工具。
- 停用或切换配置后，旧授权和迟到响应不得生效。

## 5. 数据与联网约束

本次授权覆盖本地实现、虚构数据和本地模拟测试，**不包含**真实 Jev 推理请求、上传项目资料或安装依赖。

1. 不读取实际 `.env`、密钥、生产配置或用户运行数据。
2. 不向外部服务发送源码、项目文件、历史会话、业务文档或真实日志。
3. 主模型、知识库、MCP 的授权不能复用为 Jev 授权。
4. Observe 同样需要独立发送授权。
5. 保存设置、启动程序、打开页面不得自动联网。
6. 首期固定官方接收方和模型版本，不跟随重定向，不自动切换服务商，不自动重试。
7. 授权绑定实际请求字节、来源快照、会话、运行代次、配置代次、目的地、模型和策略版本，原子消费且不可重放。
8. 请求正文、密钥、令牌和错误响应原文不得进入持久化轨迹、普通会话历史、Memory outbox 或知识库；`local_trace` 开启也不能绕过。
9. 若确实需要重新查阅官方文档，先说明必要性并按当前授权范围处理。

## 6. 质量门（真实启用前置条件）

以下是**建议验收目标，不是已达成结果**。达不到时维持观察或停用；不通过继续放宽阈值来掩盖退化。

| 场景 | 指标与拟议门槛 | 说明 |
| --- | --- | --- |
| 任务分类 | 留出集 Macro-F1 比规则至少提高 3 个百分点；中文单独不退化 | 若基线已很高，可用更少误路由证明价值，但需报告样本与区间 |
| 任务分类采纳子集 | 至少 100 个被采纳样本，准确率至少 97%，报告置信区间；适用样本覆盖率至少 30% | 高准确率不能只靠几乎全部跳过获得 |
| 失败分流 | 模糊样本分类准确率至少 95%；产品问题误阻塞率不高于 1% | 小样本出现 0 次不代表真实风险为 0，必须报告分母与区间 |
| 硬约束 | AC-003/004/007/008/009/012/014/015/017/018/020 全部通过 | 权限、外发和终态不受评分控制 |
| 延迟 | 受控模拟网络下单次超时有界；真实授权样本报告 P50/P95 和请求占用率 | 不把服务商速度宣传换算为 Kodo 整体提速 |
| 任务收益 | 在代表性任务上报告成功率、无效修复次数、总 Token、总费用、端到端耗时 | 若总体成功率下降或净收益为负，保留 Observe/Off |

**质量门未通过时**：任务分类与失败分流各自独立判定。失败分流未达门槛时保持 Observe；两个场景的 Assist 都不自动开启。

## 8. 与设计的偏差

设计第 16 节的任务表与接口形状是拟议方案。实施中按实际代码做了下列最小调整，理由与影响记录在 `plan.md` 第 8 节：

1. 授权令牌不新增独立存储层，改为壳层内存中的 `PendingDecision` 表 + 一次性原子取出（对齐 `knowledge.rs` 的 `consume_turn` 形状）。
2. 决策轨迹复用 `Step::Reasoning` 的 `diagnostics` 字段承载 `decision.v1` JSON，不新增 Core `ItemKind`、SinkEvent 或日志文件。
3. 预算家族固定取基线 TaskType 计算结果，Jev 只影响技能选择与任务通道内的类别，不影响预算。
4. 配置落盘沿用 `settings.log` 的 `key=value` 追加语义，`jev-decision` 为独立键；凭据沿用 `credentials.log` 的 `decision` 命名空间，不与 `provider.*` / `mcp.*` 混用。
