# 实现方案

- Agent 在成功的常规模型请求完成后，从该请求使用的消息和工具定义估算分类 token。沿用现有每字符比例、消息开销和图片预算。在构造用户消息时标记注入部分的字符数和文本协议工具结果的来源，元数据随消息裁剪和压缩，不参与序列化。窗口使用服务商报告的输入用量以及实际响应模型的窗口，缺少用量时在展示层采用组成估算。执行预算、压缩触发和请求协议沿用原逻辑。
- 复用 `ContextBudget`、`Compaction` 步骤以及会话事件流。把分类估算作为上下文快照的可选字段。读取已有结构化记录，以及旧 `budget`、`compact` 阶段的固定摘要格式。上下文洞察界面只使用统计字段，不读取详细 Trace 文件。
- 裁剪步骤沿用会话事件流，只写入原因和移除消息数。与原有压缩步骤一起关联同轮后续成功请求。
- 桌面端从当前会话已加载的轮次及实时步骤生成趋势。配对紧邻的完成态模型请求用于展示输出和耗时。切换趋势保留当前选择，比较时遵循 FR-006。原生模态框管理键盘焦点和 Escape。复用输入框的斜杠选择和用量环，使用桌面语义色和 Radix 主题映射。
- Rust 验证覆盖已有记录、带估算的往返和实际 Agent 请求的回退模型。Playwright 使用合成会话测试入口、实时更新、历史选择、压缩和重载，无需请求真实模型。
